# Мануал: сопоставление запчастей с группами

Программа предлагает для каждого названия запчасти группу из вашего списка (`groups.txt`), вы проверяете и исправляете, а исправления запоминаются. Чем больше проверенных данных, тем точнее подсказки.

---

## 1. Что такое `rows_matcher.json`

**Программа этот файл не использует.** Ни один `.py` не читает и не пишет его. Это старая выгрузка результатов проверки алгоритма на вашей истории.

Формат: список из 820 строк вида `[очищенное название, группа в памяти, что предложил алгоритм, уверенность]`. Это те же четыре значения, которые собирает `check_matcher_loo.py`.

Что в нём видно:
- Совпало 495 из 820 (60,4%). Это меньше нынешних 66–68%, то есть файл сделан на более ранней версии алгоритма.
- В памяти сейчас 867 записей, а в файле 820, так что он не отражает текущее состояние.
- Файл сохранён в кодировке **cp1251**, не UTF-8. При открытии как UTF-8 будет ошибка. Читать его нужно так: `open('rows_matcher.json', encoding='cp1251')`.

Вывод: файл можно удалить или оставить как архив. Для работы он не нужен. Актуальную проверку даёт `check_matcher_loo.py`, а поиск сомнительных записей памяти даёт `audit_memory.py`.

## 3. Как программа принимает решение

Для каждого названия по порядку:

1. **Память.** Название очищается, и если такая фраза уже подтверждена, берётся её группа (100%).
2. **Правила** (Настройки → «Правила»), сверху вниз, побеждает первое подходящее (100%).
3. **Ранжирование.** Для каждой группы считаются признаки: совпадение слов с названием группы, сходство с примерами из памяти, доля группы среди примеров с теми же словами, «главное слово», бонус за совпадение с названием группы. Модель превращает это в вероятность.

Важные следствия:
- **Память сильнее правил.** Если в памяти лежит ошибочная запись для точной фразы, правило её не переопределит. Исправлять нужно саму запись, назначив верную группу заново.
- 100% выдаётся только для памяти и правил. Для остальных строк уверенность отражает вероятность верного ответа: значение 0,9 означает примерно 9 верных из 10.

Как читать уверенность (по кросс-валидации):

| Уверенность | Примерно верных | Что делать |
|---|---|---|
| ≥ 0,95 | 95% | Можно принимать после беглого взгляда |
| 0,85–0,95 | 86% | Просматривать |
| 0,55–0,85 | 65–75% | Проверять каждую |
| < 0,55 | 26–40% | Считать за подсказку, решать вручную (это фильтр «Низкая уверенность») |

## 4. Работа в программе

### Основной цикл
1. **Обзор…** — выбрать Excel с запчастями. Названия столбцов задаются в Настройках (по умолчанию «Имя артикула», «Название группы», «Имя бренда», «Артикул на сайте»).
2. **1. Загрузить и сопоставить** — программа предлагает группу для каждой строки и подставляет её в «Итоговая группа».
3. Проверка таблицы (см. ниже).
4. **2. Сохранить результат** — Excel с проставленными группами.
5. **3. Сохранить лог сопоставления** — подробный лог для анализа и повторного обучения.

**Важно:** предложенные группы подставляются в таблицу сразу, но **в память попадает только то, что вы назначили вручную** (двойной клик, выбор из топ-3, протягивание и т. д.). Непроверенные предложения не запоминаются. Так и должно быть.

### Таблица
Столбцы: №, Название, Предложение, Альтернативы (топ-3), Итоговая группа, Google, Remzona.

- **Двойной клик по «Альтернативы»** — кнопки с топ-3 группами (с процентами) и кнопка «Другой вариант…» для поиска по всем группам.
- **Двойной клик по «Итоговая группа»** — поиск по всем группам: вводите название, стрелка вниз и Enter.
- **Клик по «Google»** — поиск по бренду и артикулу. **Клик по «Remzona»** — поиск названия на Remzona.
- Подсказка с полным текстом ячейки появляется при наведении курсора.

### Фильтры
«Показать все», «Только с предложением», «Только без группы», «Низкая уверенность» (уверенность < 0,55).

### Несколько строк
- Ctrl+клик и Shift+клик — выделить несколько. Ctrl+A — выделить все видимые.
- **Ctrl+D** — протянуть группу из верхней выделенной строки на остальные.
- **ПКМ → «Назначить группу выделенным строкам…»** — один выбор для всех.
- **ПКМ → «Назначить эту группу всем строкам с таким же названием»** — проставляет группу всем строкам таблицы с тем же очищенным названием, даже скрытым фильтром.
- **ПКМ → «Создать правило из строки…»** — правило «фраза → группа» из выделенной строки (фразу можно укоротить).
- **ПКМ → «Очистить группу»**, копирование ячейки и строки.

### Горячие клавиши (работают в EN и RU раскладках)
Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+A, Ctrl+D, **Ctrl+Z** (отмена последнего назначения).

**Ограничение отмены:** Ctrl+Z возвращает значение в таблице, но **не откатывает память**. Если вы по ошибке назначили не ту группу, назначьте правильную заново: запись для этой фразы перезапишется.

### Настройки
- **Столбцы и файл групп** — названия столбцов Excel, путь к `groups.txt`.
- **Обобщённые группы** — группы вроде «Болты, винты», «Гайки, шайбы». Они побеждают реже, чем конкретные. «Порог отрыва» (по умолчанию 1,5): чем он больше, тем реже побеждают обобщённые.
- **Правила** — добавить, изменить, удалить, порядок вверх/вниз, «Проверить название» для теста.
- **Автосохранение и обучение** — интервал автосохранения (по умолчанию 30 мин), кнопка «Сохранить сейчас», «Обучить по файлу исправлений…».
- **Подсказка** — встроенная справка.

## 5. Справочник функций

### `matcher.py`, класс `SmartMatcher`

**Создание:** `SmartMatcher(groups, memory_file="matching_memory.json", generic_groups=None, generic_margin=None, rules=None)`

**Основные методы:**

| Метод | Что делает |
|---|---|
| `find_best_group(name, return_debug=False, top_n=3)` | Главная функция. Возвращает `(группа, уверенность)`, а при `return_debug=True` ещё словарь `debug`: `source` (`history` / `rule` / `scoring` / `none`), `top`, `cleaned`, `head_word` и др. Группа `None`, если определить не удалось |
| `remember(name, group)` | Запоминает выбор: очищает название, кладёт в память, пересчитывает `learned`, сохраняет файл |
| `save_memory()` | Атомарная запись памяти (через временный файл), прежняя версия остаётся в `.bak` |
| `set_rules(rules)` | Задаёт правила: список `{"pattern": str, "group": str, "regex": bool}` |
| `match_rule(cleaned)` | Ищет первое подходящее правило, возвращает `(группа, шаблон)` или `None` |
| `load_history(history)` | Заменяет историю словарём и перестраивает индексы |
| `unremember_key(key)` / `restore_key(key, group)` | Временно убрать запись и вернуть. Используются в аудите и проверках (leave-one-out) |

Атрибут `memory_error` содержит текст, если файл памяти был повреждён при загрузке (приложение показывает его предупреждением).

**Внутренние методы (для разработки):**
`_clean` — очистка названия (регистр, знаки, сокращения, латиница-двойники кириллицы); `_stem` — основа слова; `_head_noun` — главное существительное; `_extract_stems_list` — список основ; `_compute_idf` / `_word_weight` — веса слов; `_knn_scores` / `_knn_detail` — сходство с примерами памяти; `candidate_features` — признаки кандидатов; `_name_bonus` — бонус за совпадение с названием группы; `_load_model` / `_logit` — загрузка и применение модели.

**Константы класса:** `MODIFIERS` (слова-модификаторы: стороны, цвета, размеры; в память не учатся), `ABBREV` (сокращения → полные слова), `TEMP` (температура запасных весов), `GENERIC_MARGIN`, `DEFAULT_GENERIC_GROUPS`, `TYPO_CUTOFF` (порог исправления опечаток), `MODEL_VERSION` (сейчас 2).

**Правила, формат:**
- Обычная фраза: очищается так же, как названия, и ищется по границам слов. Пример: `тяга рулевая → Рычаги`.
- Регулярка (`"regex": true`): ищется в очищенном названии (нижний регистр, без знаков и цифр). Пример: `^помпа$ → Водяной насос / Помпа`.
- Некорректная регулярка молча пропускается. Проверьте её кнопкой «Проверить название».

### `app_config.py`
`load_config(path)` — сохранённые настройки поверх значений по умолчанию. `save_config(data, path)` — сохраняет только известные ключи, возвращает `True` или `False`. Константы `DEFAULTS`, `DEFAULT_RULES` (стартовые правила, действуют, только если в `app_settings.json` нет ключа `rules`; сейчас там пустой список, поэтому они **не действуют**).

### `app.py`, класс `App` (основное)
`load_and_match` — шаг 1; `save_result`, `save_match_log` — шаги 2 и 3; `fill_tree` — таблица и фильтры; `open_topn_popup`, `open_search_popup` — выбор группы; `fill_down_selection` — протягивание; `apply_to_same_name` — группа всем одинаковым названиям; `create_rule_from_row` — правило из строки; `undo_last` — отмена; `autosave_tick`, `schedule_autosave` — автосохранение; `import_corrections` — обучение по файлу исправлений; `load_groups_from_file` — загрузка групп (повторы убираются).

### Скрипты
- **`train_model.py`** — переобучение (п. 6.4).
- **`check_matcher_loo.py`** — leave-one-out по истории: для каждой записи убирает её из памяти и смотрит, угадал ли алгоритм. Печатает точность и таблицу по диапазонам уверенности.
- **`audit_memory.py [порог]`** — то же, но собирает записи, где алгоритм уверенно (по умолчанию ≥ 0,75) предлагает **другую** группу. Результат в `memory_audit.xlsx`. Память не меняет.
- **`check_data.py`** — только отчёт, ничего не меняет.

## 6. Как обучать правильно

### 6.1. Главный принцип
Память — единственный источник обучения. Всё, что в неё попало, алгоритм считает истиной и будет повторять с уверенностью 100%. Ошибочная запись хуже, чем отсутствие записи.

### 6.2. Ежедневная работа
1. Загрузите файл и сопоставьте.
2. Просмотрите таблицу **целиком или хотя бы всё, что ниже 0,85**. Начинайте с фильтра «Низкая уверенность».
3. Каждую ошибку исправляйте двойным кликом. Каждое исправление автоматически обучает память.
4. Для одинаковых названий используйте «Назначить эту группу всем строкам с таким же названием», для похожих подряд идущих Ctrl+D.
5. Сохраните результат и лог.

Чего не делать:
- Не назначайте группу «на глаз» ради скорости. Одна неверная запись даёт неверные подсказки для всех похожих названий.
- Не используйте протягивание Ctrl+D по строкам, которые не проверили: оно запоминает каждую строку.
- Не рассчитывайте на Ctrl+Z для памяти (см. п. 4).

### 6.3. Что лучше: правило или память
- **Память** — для точных названий. Она обучается сама, ничего настраивать не нужно.
- **Правило** — для широкого шаблона, который всегда ведёт в одну группу: «помпа» → «Водяной насос / Помпа», «тяга рулевая» → «Рычаги». Правило срабатывает раньше ранжирования и не требует накопления примеров.
- Не делайте слишком общих правил: фраза «ремкомплект» сгребёт всё подряд. Проверяйте кнопкой «Проверить название».
- Помните: точная запись в памяти сильнее правила.

### 6.4. Переобучение модели (`train_model.py`)
Модель ранжирования (`matcher_model.json`) учится на памяти. **Она нужна для точности, но не обновляется сама.**

Когда переобучать:
- после заметного роста памяти (ориентир: +500 записей);
- **обязательно после любого изменения `groups.txt`** (модель зависит от списка групп);
- после того как вы исправили значительное число ошибочных записей в памяти.

Как:
1. Установите зависимости один раз: `pip install scikit-learn scipy numpy`.
2. Запустите из папки приложения: `python train_model.py` (1–2 минуты). Нужны рядом `groups.txt`, `app_settings.json`, `matching_memory.json`.
3. Скрипт напечатает: `CV acc` (честная точность), `temperature`, таблицу «уверенность → точность» и `parity` (должно быть порядка 1e-6, иначе сравнение с sklearn нарушено).
4. Перезапустите приложение.

Ориентиры на текущих данных: `CV acc` около 0,68, `parity` порядка 1e-6.

Как проверить, что модель подхватилась: `python check_data.py` должен написать «Модель ранжирования: загружена (версия 2, …)». Если написано «НЕ загружена», модель либо отсутствует, либо обучена старой версией скрипта (нет ключа `version`).

### 6.5. Проверки качества
- **`check_matcher_loo.py`** даёт быструю оценку, но она завышена на 4–5 п.п., потому что модель обучалась на той же истории. Настоящую оценку берите из `CV acc` в `train_model.py`.
- **`audit_memory.py`** запускайте раз в несколько партий. Он ищет записи, где алгоритм уверенно не согласен с памятью. Это кандидаты на ошибку в памяти, **но не приговор**: иногда ошибается алгоритм (например, из-за слова «механизм»). Решайте по каждой строке сами.

Как исправлять по аудиту:
1. Откройте `memory_audit.xlsx`.
2. В столбце «Верная_группа» впишите правильную группу **только** в строках, где уверены. Остальные оставьте пустыми.
3. Настройки → «Автосохранение и обучение» → «Обучить по файлу исправлений…» и выберите файл.
4. Названия групп сверяются со списком: регистр и пробелы исправятся, неизвестные группы пропустятся и будут показаны в итоговом сообщении.
5. После заметных исправлений переобучите модель (п. 6.4).

### 6.6. Обучение по логу (`match_log.xlsx`)
«Обучить по файлу исправлений…» принимает и сохранённые логи. Для лога программа спросит, что запомнить:
- **Да** (рекомендуется) — только строки, которые вы **исправили**. Непроверенные предложения в память не попадут.
- **Нет** — все строки, включая принятые без правок. Используйте, только если уверены, что проверили каждую строку, иначе ошибочные предложения станут «подтверждёнными».

Замечание по вашему `match_log.xlsx`: в нём итоговая группа равна предложенной во всех 1703 строках, то есть исправлений там нет. Ответ «Да» ничего не запомнит, ответ «Нет» запомнит всё как истину.

### 6.7. Резервные копии и восстановление
- Перед крупными действиями (импорт, аудит-исправления) сделайте копию `matching_memory.json`.
- Программа сама хранит `matching_memory.json.bak` (предыдущее состояние) и папку `remzona_groups_logs`.
- Если память повреждена, программа покажет предупреждение, восстановит её из `.bak` и сохранит повреждённый файл рядом как `*.corrupt-…`.

### 6.8. Чек-лист

**После каждой партии:** сохранить результат и лог.

**Раз в 2–3 партии:** `python check_data.py`; `python audit_memory.py`; исправить очевидные ошибки в памяти.

**При росте памяти на 500 записей и после смены `groups.txt`:** `python train_model.py`, затем перезапуск приложения.

**Если подсказки резко ухудшились:** `check_data.py` (загружена ли модель, нет ли битой памяти), затем `audit_memory.py`.

## 7. Известные ограничения
- Ctrl+Z не откатывает память (п. 4).
